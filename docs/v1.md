# Bao desktop v1

Goal: a desktop app that saves a workflow and replays it locally, in the browser and through computer use. macOS is the primary target. Inputs are collected before the run (text, secrets, numbers, choices, files). Replay does not call a model unless a step misses, and then only to heal.

## Decisions

**One Node core, two browsers.** The product window is Playwright's Chromium, bundled inside `Bao.app`, on `127.0.0.1`. The capture and replay browser is a second Playwright Chromium with an app-owned profile (`desktop/src/launch.ts`). Neither process is the user's installed Chrome, and the owned-process check matches `--user-data-dir`, not the binary path. The shell is not the page under automation. Electron was rejected because it is a second Chromium and the easy mistake is to automate that webview. Tauri was rejected for this cut because a new webview does not make lookup more trustworthy, and the macOS helper has to stay its own signed bundle (`dev.bao.oshelper`) so Accessibility grants survive. The UI, the CLI, and the MCP server call `desktop/src/v1/replay.ts`. `bao mcp` is the agent server: the four-tool catalog (`search_workflows`, `describe_workflow`, `run_workflow`, `get_run`) plus the `live_*` tools, which go to the running app. `bao mcp-ax` is the macOS Accessibility driver in `desktop/src/proxy/mcp-bao.ts`.

**Identity, then refuse.** `docs/element-identity.md`. Score at least 60, and lead the next candidate by 25, or stop. Coordinates stay on `provenance`.

**Schema v2 is the contract.** `schema/workflow-v2.schema.json`. Interpret is deterministic and is enough to replay. Secrets and file paths are inputs, not literals. Property tests cover that.

**Healing defaults to auto.** A miss first tries a cheap repair from the step's recorded intent: label similarity, position against an anchor, closing a known overlay, then a wait for the element or for network idle. The repair name is on the run and in the trail. A model heal runs only after those refuse. If `OPENAI_API_KEY` or `ANTHROPIC_API_KEY` is set, that model proposes a patched step and replay continues without waiting. When `agent status --format json` reports `isAuthenticated: true`, bao runs `agent --print --mode ask` and that request bills the Cursor account. bao does not read or pass an API key. The prompt is the heal text on stdin, not an argument. `BAO_HEAL_CURSOR=1` is the fallback when that CLI is missing, logged out, or the print process fails: it writes the failure screenshot and waits for `heal-response.json` in `BAO_HEAL_DIR`. The patch in that file is the heal. `BAO_HEAL_CURSOR_ACCOUNT=0` skips the CLI. A model heal that passes is saved as provisional. It becomes permanent only after the six-change drift suite and the next real runs pass. The default is three passing runs, and Settings can change that count. If either check fails, the saved step is put back. A step can set its own policy to auto, ask, or never, so a confirm or Apply step can refuse a model. Before any model call, a miss is sorted into a real change, a temporary blocker, or an outage. Only a real change is healed. Auto-heal also stops when three runs of that workflow fail within ten minutes. Each of those states is a `promotion` event on the trail. The heal is an append-only record: the failed step, its intent, the screenshot plus the a11y and DOM snapshot, the prompt, the model name and version, the raw response, the patch, what ran, and whether the postcondition then passed. The prompt text records the snapshot without the PNG bytes; the bytes stay on the record. Secrets in that record are replaced with `[secret]`. The app shows a notice, `notify-send` / a macOS notification fires, and the run and the workflow get a heal badge. Keep writes the patch into the saved workflow. Revert puts the failed step back. Both append a decision and leave the heal record as it was. Settings → “When a step misses”, and the per-workflow control on Replay, switch this to `approve`, which pauses on the proposal. With no vendor key, no logged-in Cursor CLI, and without `BAO_HEAL_CURSOR`, healing is off and replay stops on the structured failure, which names the phase. `BAO_HEAL_FIXTURE=1` is a local stand-in used to film the notification. Its model name is `bao-heal-fixture` version `1`. It is not a vendor model. The Versions panel is that history. Each version holds the locator it recorded: the local time with its zone, the source (recorded, heal, revert, or rollback), the source run, the score, and which attributes changed. Restore saves that version as a new draft and leaves the older versions as they were. Replay keeps the live file until the draft is promoted. A cookie banner, a modal, or a spinner can be dismissed for this run only, at most three times. The run viewer logs `recovered:` and the reason. That dismiss is not written into the workflow. A CAPTCHA, a 5xx response, and a signed-out page stay failures and are not healed.

## Open

- Which real apps and sites v1 targets, beyond the fixture page and `baocalc.py`.
- Whether a vendor-key heal uses Alex's keys. Until a key is present, that path stays off. A Cursor-billed heal is the CLI login above. The response file is the fallback. MCP sampling is not a path: Cursor does not implement it.
- GTK 4 extents are still origin `(0, 0)`. The Linux demo is GTK 3 on purpose.
- A file drag from the mac helper. `CGEvent` moves the pointer and does not start an `NSDraggingSession`. Replay uses the Open panel. See `docs/files-and-drag.md`.
- Notarization, Developer ID, auto-update. Not in this cut.

## Install and run

From a checkout, after `npm install` and `npx tsc -p tsconfig.desktop.json`:

```sh
npm run bao -- serve --port 4787
```

The home is `~/Library/Application Support/bao` on macOS and `~/.local/share/bao` on other systems. Pass `--home` only to point at a different directory. An explicit `--home` or `BAO_HOME` is used as given, even when it is empty. Without one, Bao keeps an older library in `~/.local/share/bao` or `./.bao-mcp` when the default directory has no workflows or library data. When two directories both hold library data, Bao says `library data is at <other>; using <home>` once: in an alert when Finder opens Bao, or in the Library screen. `shown-notices.json` in the home records each message that was shown.

Open Bao. The window title is Bao, and there is no address bar. The left rail is Library, Capture, Teach, Runs, Heals, Replay, Logins, and Settings. Its footer shows whether a capture is recording (the dot is red only then), the Mac helper (`helper off`, `helper ok`, or `helper needs permission`), the model (`no model`, `fixture model`, `cursor account`, or `model ready`), and a count of items waiting on the person. Trail is a tab inside Capture and inside a run, not a sidebar item. `⌘K` (or Ctrl+K) opens a command list of screens and workflows. `/` focuses Library search. Appearance is light or dark from the same tokens (`data-theme` on the document, stored in this browser as `bao-theme`). Status colors are passed, healed, provisional, needs you, and failed.

The visible window waits 1 second after each state read when idle, or 100 ms during active work. Replays and Guide me started in the window refresh at once and keep the fast rate while their requests are pending. A restored ask or an old guide or live-session record alone does not keep fast updates on. Hidden windows wait at least 5 seconds between scheduled reads, so prompt expiry and scheduled backups still run. Showing the window refreshes at once. Failed reads back off from 500 ms to 10 seconds, with the same hidden-window minimum; a successful read resets the delay. `desktop/src/app/state-poll.ts` defines this policy, covered by `desktop/test/unit/state-poll.test.ts`.

On macOS, while Accessibility, Screen Recording, or Automation for Google Chrome is missing, Library shows one collapsible card, “Three permissions on the Mac.” Continue stores `bao-onboarded` in this browser. After that, and on every other screen, the same list is a dot in the sidebar footer. The Automation row stays in that list: granted, not yet asked, denied, or neutral when Chrome is closed or the check is unavailable. Only not yet asked and denied count as missing Automation. A closed Chrome shows “Chrome isn't running, so Bao can't check this right now”. An unavailable check shows its real error, such as “BaoOSHelper is older than this Bao; rebuild it”, without a need dot or bringing back the card. Linux does not show either one; the footer reads `helper off`. The act bar stays above the page whenever a person still has to act.

## Live model

A live trail is labeled `source.agent: "live-model"`. A scripted driver is `scripted-driver`. Bao does not call OpenAI or Anthropic for these runs.

On alex-jxp, Codex (`gpt-6-astra` through the ChatGPT.app CLI, not an API key in bao) drove `mcp-bao.ts`. Calculator reached `12` for `7 + 5`. The trail has extra screenshots and three presses on Clear / All Clear before the keys that matter. `interpretOs` drops screenshot reads and unresolved clicks, cuts everything through the last Clear, and lifts the two digit presses into `{{a}}` and `{{b}}`. The saved steps are `{{a}}`, `Add`, `{{b}}`, `Equals`. Replay of `3+4` and `8+1` read `7` and `9` with the window moved. `AXSize` returns `-25200`, so a resize row for Calculator is `n/a`, not a pass. TextEdit collapsed to one `osSetValue` of `{{text}}`. Replay wrote `alpha one` and `beta two`. The window title flips between `Untitled` and `Untitled.rtf`; lookup treats those as the same document. The text area is `AXIdentifier` `First Text View`.

A scripted driver records one act per planned control and does not insert screenshot reads or Clear retries. Interpret's job on the live trail is to drop those and still leave a workflow that replays by identity.

On this Linux session the same stdio server was driven one screenshot at a time, with no vendor API call. The login trail is `source.agent: "live-model"`, `vendor: "cursor"`, `adapter: "stdio"`. It has a screenshot before the form and another after the secure page. Interpret dropped both reads and kept click, type `{{username}}`, click, type the secret (no stored value), click Login. Replay with healing unavailable passed twice, with the page pushed down 220px and 90px. The site accepts only the one public credential pair, so those two replays change the page, not the password. The upload trail has an extra screenshot, an unresolved click on the file input (the path is not an action; interpret drops it), an upload step whose value is `{{file}}`, and a click whose postcondition is the text `File Uploaded!`. Replay passed for `note-b.txt` with the page pushed down 180px and for `note-a.txt` pushed down 40px. An earlier abandoned upload in the same home had clicked Upload before a file was chosen and had clicked a link; those events were left out of this workflow. Interpret would have kept them, and the replay would have clicked Upload too early.

## Expect, repair, promote

A step may declare `expect` (text, element state, or URL). Replay reads it after the action. A workflow can end in a `verify` step that only re-reads. The local page is `GET /freeze`: Frozen and Open radios, Apply, and a status line. `examples/workflows/credit-freeze.json` checks the Frozen radio, expects `Status: Frozen` after Apply, and verifies that text again. `?stuck=1` leaves the status at `Status: none`, and the verify step fails with phase `expect`. `?overlay=1` covers the form until Dismiss. That click is the `overlay` repair. The run passes with no heal. `?heal=1` renames Apply to Continue and keeps `data-testid=apply`. The recorded intent `Submit freeze` does not match Continue, so the four repairs refuse and the Cursor heal runs.

The drift suite was 24/24 before this change (`docs/drift-linux-before.md`, generated `2026-10-21T03:22:56.632Z`) and 24/24 after (`docs/drift-linux.md`, generated `2026-10-21T15:55:33.426Z`). Each of shift, theme, font, order, slow, and scale-2x was 4/4. The four captured steps were each 6/6. The failures table is empty both times. The live drift capture is a fresh login workflow, so the new verify step is not one of those four rows.

On the heal recording, the failure screenshot showed Frozen selected, a button labeled Continue, and `Status: none`. The DOM dump on that same failure gave the button test id `apply`. The response file named that identity. The model on the audit is `cursor` version `live`. The run passed, the badge was provisional, and Check promotion runs the six drift changes plus the later real runs. The default is three. The badge becomes promoted only after those pass. The trail records each promotion event: provisional, drift, then each real run. No OpenAI or Anthropic call was made.
