# Bao desktop v1

Goal: a desktop app that saves a workflow and replays it locally, in the browser and through computer use. macOS is the primary target. Inputs are collected before the run (text, secrets, numbers, choices, files). Replay does not call a model unless a step misses, and then only to heal.

## Decisions

**One Node core, two browsers.** The product window is Playwright's Chromium, bundled inside `Bao.app`, on `127.0.0.1`. The capture and replay browser is a second Playwright Chromium with an app-owned profile (`desktop/src/launch.ts`). Neither process is the user's installed Chrome, and the owned-process check matches `--user-data-dir`, not the binary path. The shell is not the page under automation. Electron was rejected because it is a second Chromium and the easy mistake is to automate that webview. Tauri was rejected for this cut because a new webview does not make lookup more trustworthy, and the macOS helper has to stay its own signed bundle (`dev.bao.oshelper`) so Accessibility grants survive. The UI, the CLI, and the Linux MCP server call `desktop/src/v1/replay.ts`. On macOS, `bao mcp` is `desktop/src/proxy/mcp-bao.ts`.

**Identity, then refuse.** `docs/element-identity.md`. Score at least 60, and lead the next candidate by 25, or stop. Coordinates stay on `provenance`.

**Schema v2 is the contract.** `schema/workflow-v2.schema.json`. Interpret is deterministic and is enough to replay. Secrets and file paths are inputs, not literals. Property tests cover that.

**Healing defaults to auto.** On a missed lookup or a failed postcondition, if `OPENAI_API_KEY` or `ANTHROPIC_API_KEY` is set, the model proposes a patched step and replay continues without waiting. The heal is an append-only record: the failed step, its intent, the screenshot plus the a11y and DOM snapshot, the prompt, the model name and version, the raw response, the patch, what ran, and whether the postcondition then passed. The prompt text records the snapshot without the PNG bytes; the bytes stay on the record. Secrets in that record are replaced with `[secret]`. The app shows a notice, `notify-send` / a macOS notification fires, and the run and the workflow get a heal badge. Keep writes the patch into the saved workflow. Revert puts the failed step back. Both append a decision and leave the heal record as it was. Settings → “When a step misses”, and the per-workflow control on Replay, switch this to `approve`, which pauses on the proposal. With no key, healing is off and replay stops on the structured failure. `BAO_HEAL_FIXTURE=1` is a local stand-in used to film the notification. Its model name is `bao-heal-fixture` version `1`. It is not a vendor model.

## Open

- Which real apps and sites v1 targets, beyond the fixture page and `baocalc.py`.
- Whether a real-model heal uses Alex's keys. Until a key is present, heal stays off.
- GTK 4 extents are still origin `(0, 0)`. The Linux demo is GTK 3 on purpose.
- A file drag from the mac helper. `CGEvent` moves the pointer and does not start an `NSDraggingSession`. Replay uses the Open panel. See `docs/files-and-drag.md`.
- Notarization, Developer ID, auto-update. Not in this cut.

## Install and run

From a checkout, after `npm install` and `npx tsc -p tsconfig.desktop.json`:

```sh
npm run bao -- serve --home ~/.local/share/bao --port 4787
```

Open `http://127.0.0.1:4787`. The left rail is Library, Capture, Runs, Heals, and Settings. Its footer shows whether a capture is recording (the dot is red only then), the Mac helper (`helper off`, `helper ok`, or `helper needs permission`), the model (`no model`, `fixture model`, or `model ready`), and a count of items waiting on the person. Trail is a tab inside Capture and inside a run, not a sidebar item.

| Mode | How |
| --- | --- |
| Library | The saved workflows. Each row has a Run button. Rename, delete (confirm), edit the JSON, import, and export sit under the table. |
| Browser capture | Capture → Start capture. The owned Chrome opens the URL. Stop and save runs interpret and writes the workflow under the home directory. The Trail card on this screen loads a capture. Password values are not in it. |
| Run | Library → Run, or a row on Runs. Fill every input, including files by picker or drop. A run opens in the viewer: the step that stopped, one progress segment per step, before and after screenshots, an identity table (score, lead, matched attributes), and a model-call badge. `0 model calls` is the passing case with healing unused. When a step has `startedAt`, the viewer draws a marker; a webm is saved only if `BAO_RUN_VIDEO=1`. |
| Heals | Recorded target beside the proposed target, a before/after slider when both screenshots exist, other candidates, and the prompt and raw response folded shut. Keep writes the patch into the saved workflow. Revert puts the failed step back. Both append a decision. The heal record is not edited. |
| Settings | Auto self-heal, or approve before applying. Replay can override that per workflow. |
| You need to act | A bar on every screen while a `login` step, a `confirm` step, or a site-login consent is waiting. It names the button and the window, and counts down to the step timeout. A confirm step has no approve control in Bao: the person presses the site's own button, and the postcondition is how Bao sees that it happened. Timeout of a confirm stops with `nothing applied`. A login step adds `I'm signed in, continue`. The same bar fires a notification (`notify-send` on Linux, a macOS notification on Darwin) and, if the product window already has permission, a browser notification. |
| Import a site login | `bao import-login --from chrome --domain experian.com`. The Bao window asks first. Only that site's cookies are copied, then injected with `Network.setCookies`. The audit line is the domain, the count, and the time. A failure is rendered from `ImportLoginError` (`desktop/src/v1/import-login-error.ts`): `code`, `cause`, `hint`, and an optional scrubbed `detail`. The Mac agent owns detection and should set those fields. `safeImportError` still returns an allowlisted string; the window maps that string onto the same shape. Import logic is unchanged. |
| MCP | `npm run bao -- mcp` on stdio. Linux tools: `screenshot`, `click`, `type`, `key`, `scroll` (`BAO_MCP_LIVE=1` drives the owned browser; the default stub records only). macOS tools are Calculator and TextEdit via `mcp-bao.ts`: `screenshot`, `click`, `type`, `key`, `read_tree`. |
| Claude Code observer | `desktop/mcp/claude/`. The hook logs the built-in computer tool into `~/.local/share/bao/observer/trail.jsonl` and does not perform it. |
| Proxy | Executors are `desktop/src/proxy/openai.ts` and `claude.ts`. The serve port does not mount them yet. A key is not required to capture. |
| Tests | `npm test` (extension) and `npm run test:v1` (schema, identity, interpret, heal, replay, MCP). Live: `desktop/test/live/`. |
| Linux package | `bash desktop/packaging/linux/build-appimage.sh` |
| macOS package | `bash desktop/packaging/macos/package-app.sh` on alex-jxp. See `docs/mac-test.md`. |

Data stays under the `--home` directory: `workflows/`, `trails/`, `runs/` (heal records and keep/revert decisions), `settings.json`, and `audit/import-login.jsonl` (domain, cookie count, timestamp). A `confirm` step and a `login` step wait for the person. Replay does not click or type them. `replayed: false` means the workflow has not been replayed.

## Live model

A live trail is labeled `source.agent: "live-model"`. A scripted driver is `scripted-driver`. Bao does not call OpenAI or Anthropic for these runs.

On alex-jxp, Codex (`gpt-6-astra` through the ChatGPT.app CLI, not an API key in bao) drove `mcp-bao.ts`. Calculator reached `12` for `7 + 5`. The trail has extra screenshots and three presses on Clear / All Clear before the keys that matter. `interpretOs` drops screenshot reads and unresolved clicks, cuts everything through the last Clear, and lifts the two digit presses into `{{a}}` and `{{b}}`. The saved steps are `{{a}}`, `Add`, `{{b}}`, `Equals`. Replay of `3+4` and `8+1` read `7` and `9` with the window moved. `AXSize` returns `-25200`, so a resize row for Calculator is `n/a`, not a pass. TextEdit collapsed to one `osSetValue` of `{{text}}`. Replay wrote `alpha one` and `beta two`. The window title flips between `Untitled` and `Untitled.rtf`; lookup treats those as the same document. The text area is `AXIdentifier` `First Text View`.

A scripted driver records one act per planned control and does not insert screenshot reads or Clear retries. Interpret's job on the live trail is to drop those and still leave a workflow that replays by identity.

On this Linux session the same stdio server was driven one screenshot at a time, with no vendor API call. The login trail is `source.agent: "live-model"`, `vendor: "cursor"`, `adapter: "stdio"`. It has a screenshot before the form and another after the secure page. Interpret dropped both reads and kept click, type `{{username}}`, click, type the secret (no stored value), click Login. Replay with healing unavailable passed twice, with the page pushed down 220px and 90px. The site accepts only the one public credential pair, so those two replays change the page, not the password. The upload trail has an extra screenshot, an unresolved click on the file input (the path is not an action; interpret drops it), an upload step whose value is `{{file}}`, and a click whose postcondition is the text `File Uploaded!`. Replay passed for `note-b.txt` with the page pushed down 180px and for `note-a.txt` pushed down 40px. An earlier abandoned upload in the same home had clicked Upload before a file was chosen and had clicked a link; those events were left out of this workflow. Interpret would have kept them, and the replay would have clicked Upload too early.
