# Bao desktop v1

Goal: a desktop app that saves a workflow and replays it locally, in the browser and through computer use. macOS is the primary target. Inputs are collected before the run (text, secrets, numbers, choices, files). Replay does not call a model unless a step misses, and then only to heal.

## Decisions

**One Node core, separate browser targets.** The shell is not the page under automation; [Mac launch](mac-build.md#launch) owns its window and process lifecycle. [Select the driver](extension.md#select-the-driver) owns browser selection; [Agent-browser pass-through](agent-browser-engine.md) owns its browser choices and workflow limits. The macOS helper stays its own signed bundle (`dev.bao.oshelper`) so Accessibility grants survive. The UI, the CLI, and the MCP server call `desktop/src/v1/replay.ts`. `bao mcp` is the agent server; [MCP](bao.md#mcp) owns its tool routes. `bao mcp-ax` is the macOS Accessibility driver in `desktop/src/proxy/mcp-bao.ts`.

**Identity, then refuse.** `docs/element-identity.md`. Score at least 60, and lead the next candidate by 25, or stop. Coordinates stay on `provenance`.

**Schema v2 is the contract.** `schema/workflow-v2.schema.json`. Interpret is deterministic and is enough to replay. Secrets and file paths are inputs, not literals. Property tests cover that.

**Healing defaults to auto.** A miss first tries a cheap repair from the step's recorded intent: label similarity, position against an anchor, closing a known overlay, then a wait for the element or for network idle. The repair name is on the run and in the trail. A model heal runs only after those refuse. If `OPENAI_API_KEY` or `ANTHROPIC_API_KEY` is set, that model proposes a patched step and replay continues without waiting. When `agent status --format json` reports `isAuthenticated: true`, bao runs `agent --print --mode ask` and that request bills the Cursor account. bao does not read or pass an API key. The prompt is the heal text on stdin, not an argument. `BAO_HEAL_CURSOR=1` is the fallback when that CLI is missing, logged out, or the print process fails: it writes the failure screenshot and waits for `heal-response.json` in `BAO_HEAL_DIR`. The patch in that file is the heal. `BAO_HEAL_CURSOR_ACCOUNT=0` skips the CLI. A model heal that passes is saved as provisional. It becomes permanent only after the six-change drift suite and the next real runs pass. The default is three passing runs, and Settings can change that count. If either check fails, the saved step is put back. A step can set its own policy to auto, ask, or never, so a confirm or Apply step can refuse a model. Before any model call, a miss is sorted into a real change, a temporary blocker, or an outage. Only a real change is healed. Auto-heal also stops when three runs of that workflow fail within ten minutes. Each of those states is a `promotion` event on the trail. The heal is an append-only record: the failed step, its intent, the screenshot plus the a11y and DOM snapshot, the prompt, the model name and version, the raw response, and, when available, the patch, what ran, and whether the postcondition then passed. An OpenAI or Anthropic request that fails or returns no usable identity still records the model, prompt, and any response body read, and counts as one model call. Replay then fails without applying a patch or asking for approval. `desktop/test/unit/heal-source.test.ts` covers these failed attempts. The prompt text records the snapshot without the image bytes; the bytes stay on the record. Secrets in that record are replaced with `[secret]`. The app shows a notice, `notify-send` / a macOS notification fires, and the run and the workflow get a heal badge. See the Heals row under [Install and run](#install-and-run) for target review and manual Keep/Revert decisions. Settings → Runs and heals → When a page changes → Ask me, and the per-workflow control on Replay, switch this to `approve`, which pauses on the proposal. With no vendor key, no logged-in Cursor CLI, and without `BAO_HEAL_CURSOR`, healing is off and replay stops on the structured failure, which names the phase. `BAO_HEAL_FIXTURE=1` is a local stand-in used to film the notification. Its model name is `bao-heal-fixture` version `1`. It is not a vendor model. The Versions panel is that history. Each version holds the locator it recorded: the local time with its zone, the source (recorded, heal, revert, or rollback), the source run, the score, and which attributes changed. Restore saves that version as a new draft and leaves the older versions as they were. Replay keeps the live file until the draft is promoted. A cookie banner, a modal, or a spinner can be dismissed for this run only, at most three times. The run viewer logs `recovered:` and the reason. That dismiss is not written into the workflow. A CAPTCHA, a 5xx response, and a signed-out page stay failures and are not healed.

## Open

- Which real apps and sites v1 targets, beyond the fixture page and `baocalc.py`.
- Whether a vendor-key heal uses Alex's keys. Until a key is present, that path stays off. A Cursor-billed heal is the CLI login above. The response file is the fallback. MCP sampling is not a path: Cursor does not implement it.
- GTK 4 extents are still origin `(0, 0)`. The Linux demo is GTK 3 on purpose.
- A file drag from the mac helper. `CGEvent` moves the pointer and does not start an `NSDraggingSession`. Replay uses the Open panel. See `docs/files-and-drag.md`.
- Notarization, Developer ID, auto-update. Not in this cut.

## Install and run

From a checkout, after `npm install` and `npx tsc -p tsconfig.desktop.json`:

```sh
npm run bao -- serve --port 4787
```

The home is `~/Library/Application Support/bao` on macOS and `~/.local/share/bao` on other systems. Pass `--home` only to point at a different directory. An explicit `--home` or `BAO_HOME` is used as given, even when it is empty. Without one, Bao keeps an older library in `~/.local/share/bao` or `./.bao-mcp` when the default directory has no workflows or library data. When two directories both hold library data, Bao says `library data is at <other>; using <home>` once: in an alert when Finder opens Bao, or in the Library screen. `shown-notices.json` in the home records each message that was shown.

Open Bao. [Mac launch](mac-build.md#launch) describes the native window and its drag strip. Runs opens first. The sidebar has three places: Runs, Workflows, and Settings. The Workflows list and workflow detail fill the space beside the sidebar, with no middle screens pane. Record opens Capture without the sidebar or middle screens pane. Before recording, Back to Workflows returns to the list. Capture’s Teach control and the command list keep Teach reachable. The command list also opens Replay. Other screens keep their second pane: Runs, Live, and Heals under Runs; Teach and Replay under Workflows. Settings has a section index for Runs and heals, Mac permissions, Remote access, Logins, and AI help. Import a login… in Settings or the command list opens Logins. The right pane shows the selected screen or receipt. The sidebar footer shows Bao with the number of waiting runs and steps needing review, plus a notice when a sign-in import needs you. With none of those, it shows Recording, Running, or Nothing running. Clicking it opens the first waiting run (or Live for an ask without a stored waiting run), then Logins for an import, then Library for a step review; otherwise it opens Live. Helper and model status live in Settings, not the footer. Trail is a tab inside Capture and inside a run, not a sidebar item. `⌘K` (or Ctrl+K) opens a command list of screens and workflows. `/` focuses Library search. Appearance is light or dark from the same tokens (`data-theme` on the document, stored in this browser as `bao-theme`). Status colors are passed, healed, provisional, needs you, and failed.

The visible window waits 1 second after each state read when idle, or 100 ms during active work. Replays and Guide me started in the window refresh at once and keep the fast rate while their requests are pending. A restored ask or an old guide or live-session record alone does not keep fast updates on. Hidden windows wait at least 5 seconds between scheduled reads, so prompt expiry and scheduled backups still run. Showing the window refreshes at once. Failed reads back off from 500 ms to 10 seconds, with the same hidden-window minimum; a successful read resets the delay. `desktop/src/app/state-poll.ts` defines this policy, covered by `desktop/test/unit/state-poll.test.ts`.

[Which grant each job needs](permissions.md#which-grant-each-job-needs) explains the optional native-app driver, remote-debugging CLI, helper labels, and Settings → Mac permissions rows. The default copied-profile Chrome route needs no Accessibility, Automation, or Screen Recording grant. Explicit current-Chrome control uses the helper's existing Accessibility grant. The retired daily-Chrome permission card, sidebar dot, Automation Allow button, and prompt notice are gone. Missing optional grants do not block onboarding or create footer warnings. The [handoff controls](#you-need-to-act) stay visible while a person still has to act.

A workflow file that cannot be read, parsed, or validated does not hide the other workflows. The Workflows sidebar item shows a red warning glyph with a text description. Library shows a damaged-file banner. **Show in Finder** opens this Library’s workflow folder. Open a damaged file’s name to show **File details and recovery**, with each file’s reason, path, and recovery steps. If the folder cannot open, Bao shows that control and a plain error. Use Finder’s Go → Go to Folder to reach the path, then restore a backup, fix the file, or move it out of `workflows/`. **Record again** opens Capture to make a new workflow. If no workflows can open, Library says so instead of “No workflows yet.” Listing leaves the files unchanged; [sync](bao.md#run-it-locally) has its own damaged-file rules. `desktop/test/unit/damaged-library.test.ts` covers isolation and recovery.

## You need to act

Opening a run with the current active ask shows its live-run detail, not its receipt or a past live-session record. The detail names the workflow, the start and pause times in the local zone, the requested action, and the deadline with time left, or no timeout. It replaces the separate act bar on this screen; other screens keep the bar, which names the button and window and states when the wait times out. Site-login consent also uses the bar. The default wait is 120 minutes.

Steps show saved results, the current handoff, and steps not yet run. The preview shows the latest saved step picture, not a live video feed. Screens so far shows the available saved pictures. While the person has control, step screenshots and trail capture pause; the trail logs handoff start and end with the local zone. Missing pictures and unavailable steps have explicit empty states. Run details starts collapsed and holds saved inputs, the driver label, model-call count when available, and the run ID.

Show Bao’s Chrome uses the existing replay-window control. Press a confirmation button on the site itself; `I pressed <button>` does not press it or bypass a postcondition. During a running confirmation wait with a postcondition, Bao checks that condition to see whether the action happened. A login ask offers I’m signed in, continue; other asks offer Continue. Stop run… opens a confirmation dialog. Keep waiting leaves the run alone; Stop run stops it without undoing actions already taken on the site. Open workflow opens the saved workflow, and the search button opens the command list.

If the ask clears while this detail stays open and replay continues, the detail shows Running, hides the deadline, and disables Continue. It shows the next ask when one arrives and opens the receipt once replay ends. `desktop/test/unit/live-view.test.ts` covers the handoff view, navigation, continuation, and stop controls.

A login or confirm ask persists in the app home as `pending-prompt.json`. The next launch restores the ask and the badge. After the deadline, with no replay still in that wait, Bao removes the prompt and marks the run stopped, timed out. A wait that times out inside a running replay stops with `nothing applied` for a confirm or `waiting for you to log in` for a login.

The act bar also appears when one step has healed itself on 3 runs in a row. That step is marked needs review, and auto-heal stays off for it until a later run passes the step without a heal. The same moment fires a notification (`notify-send` on Linux, a macOS notification on Darwin), a count on the sidebar, and a Dock badge. The window title stays Bao.

## Known gaps

Settings still restores a backup without confirmation. The footer's helper, model, and account labels still lack next-step guidance. Unused permission-dot CSS and `ShellState` permission fields remain for later cleanup. The global Stop choice belongs to a later part of the Settings redesign.

Devices still says Settings > Sync. In Bao, open Settings > Technical details > Sync. The pairing field under Remote access connects remote agents, not sync.

The Remote access switch can show Off while the launch-time developer override `BAO_REMOTE_MCP` enables remote access. The owner app does not set this override.

## Live model

A live trail is labeled `source.agent: "live-model"`. A scripted driver is `scripted-driver`. Bao does not call OpenAI or Anthropic for these runs.

On alex-jxp, Codex (`gpt-6-astra` through the ChatGPT.app CLI, not an API key in bao) drove `mcp-bao.ts`. Calculator reached `12` for `7 + 5`. The trail has extra screenshots and three presses on Clear / All Clear before the keys that matter. `interpretOs` drops screenshot reads and unresolved clicks, cuts everything through the last Clear, and lifts the two digit presses into `{{a}}` and `{{b}}`. The saved steps are `{{a}}`, `Add`, `{{b}}`, `Equals`. Replay of `3+4` and `8+1` read `7` and `9` with the window moved. `AXSize` returns `-25200`, so a resize row for Calculator is `n/a`, not a pass. TextEdit collapsed to one `osSetValue` of `{{text}}`. Replay wrote `alpha one` and `beta two`. The window title flips between `Untitled` and `Untitled.rtf`; lookup treats those as the same document. The text area is `AXIdentifier` `First Text View`.

A scripted driver records one act per planned control and does not insert screenshot reads or Clear retries. Interpret's job on the live trail is to drop those and still leave a workflow that replays by identity.

On this Linux session the same stdio server was driven one screenshot at a time, with no vendor API call. The login trail is `source.agent: "live-model"`, `vendor: "cursor"`, `adapter: "stdio"`. It has a screenshot before the form and another after the secure page. Interpret dropped both reads and kept click, type `{{username}}`, click, type the secret (no stored value), click Login. Replay with healing unavailable passed twice, with the page pushed down 220px and 90px. The site accepts only the one public credential pair, so those two replays change the page, not the password.
