# Test Bao through desktop clients

With Bao open and ChatGPT in **Codex** mode, run `node scripts/test-desktop-clients.mjs --output /absolute/local/evidence` using a new local output directory. It needs `chrome-devtools-axi` on PATH and Bao registered at its installed launcher. It reads X, GitHub, Gmail and LinkedIn with both `copy` and `bao`; add `--site x.com` for a focused pass. It uses your sign-ins, creates chats and Library runs, restarts ChatGPT with localhost CDP, then restores a normal launch. It leaves your running Chrome alone and requests no Mac grants.

Claude Desktop 4.23118.0 rejects CDP launch flags, so this runner does not drive that window. The Claude path is claude.ai plus the connected Mac. Run `node scripts/test-desktop-clients.mjs --client claude --site github.com --output /absolute/local/evidence`. It drives claude.ai through the installed Bao MCP with `browser=current`, in a Bao-created tab only. It stops, and changes nothing, when that chat does not show the Mac as Connected. It exercises Claude's tools on this Mac. Bao shows there as plain tool rows rather than the picture card. It clicks Allow once only, never Always allow. It closes only its own tab and disconnects. It does not quit Chrome. A copy reply that does not say the profile copy was deleted is not a pass, even when the Library run closed.

Keep the output on this Mac. Open the conversation/tool-card, site and Bao receipt pictures, then read each `result.json`; a captured run does not prove a working sign-in. A nonzero exit needs review.
