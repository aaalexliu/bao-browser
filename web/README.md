# Deploy Bao on Vercel

Eight clicks. This repo does not deploy itself. From `web/`, `npx vercel@65.0.0 build --yes` writes `.vercel/output` and does not deploy. Logged out, that command asks to pull project settings. A local `web/.vercel/project.json` with `settings.framework` set to `nextjs` lets the build finish without a login.

1. Open [vercel.com/new](https://vercel.com/new) and import the GitHub repository `aaalexliu/bao-browser`.
2. Root Directory: click **Edit**, enter `web`, then Continue. Framework Preset: **Next.js**. Leave the build command as `npm run build`.
3. On your machine, run `openssl rand -hex 32`. That value is the invite secret. Do not commit it, and do not paste it into this repo. Environment Variables: add `BAO_OWNER_EMAIL` (the one email that may sign in) and `BAO_INVITE_SECRET` (that secret, marked Sensitive). Set both. Do not set `BAO_AUTH_STUB`. Production refuses to start if `BAO_AUTH_STUB` is set. Do not type `DATABASE_URL`, `BLOB_STORE_ID`, `BLOB_READ_WRITE_TOKEN`, `BAO_PG_DIR`, or `BAO_BLOB_DIR`. The last two are local directories only.
4. Click **Deploy**. Leave **Standard Protection** on (Settings → Deployment Protection). It blocks preview URLs and the generated deployment URL, and it leaves the production domain open. Do not choose **All Deployments**. That protects the production domain too. The Mac sends only its device token, which is not a Vercel login, so a protected URL rejects sync. When the deployment is Ready, copy the production domain with no trailing slash and no path. Example: `https://bao-browser.vercel.app`. Do not copy a preview URL, and do not copy the generated deployment URL.
5. In the project, open **Storage**, then **Create**, then **Blob**. Choose **Private**. Create the store and connect it to this project. That sets `BLOB_STORE_ID` for the redacted PNGs. Do not choose a public store.
6. Open [Neon on the Marketplace](https://vercel.com/marketplace/neon). Install it, choose the **Free** plan, read the plan, and accept. Connect the database to this project. Neon sets `DATABASE_URL`. Do not install Vercel Postgres or Vercel KV. Those products are sunset.
7. Open **Deployments**, open the menu on the latest deployment, and click **Redeploy**. The new deployment has to see `DATABASE_URL`, `BLOB_STORE_ID`, `BAO_OWNER_EMAIL`, and `BAO_INVITE_SECRET`.
8. On the site, sign in with the owner email and the invite secret, then open the sign-in link the page shows. Open **Devices** and copy the pairing code. On the Mac, open **Settings → Sync**. Server: paste the production domain from step 4. Pairing code: paste the code. Invite secret: paste the secret once. Name the device, then **Pair**, then **Sync**. Later syncs send the device token only. The secret stays in that Mac's sync file.

Sign-in accepts that email only, and only with the secret. A local build with neither variable set still returns the link for any email, which is how `vercel dev` tests pair. Do not turn that on for the public URL.
